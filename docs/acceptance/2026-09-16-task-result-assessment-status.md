## 浏览器检查的方法与限制

环境的Chromium禁止访问本机HTTP地址（ERR_BLOCKED_BY_ADMINISTRATOR）；这次直接浏览器网络访问未完成，不能记录为通过。

随后在Chromium中离线加载真实Vue生产JS/CSS，页面fetch通过测试适配器调用实际FastAPI TestClient / TaskService / ScheduleService。仅OpenClaw及手动分类的模型返回为合成响应，不使用端侧日志、图片、GPU或真实业务模型。它验证页面与后端契约，不证明部署环境中的浏览器网络连通或模型判断准确。

修正后的9组检查通过：

1. 普通任务默认不评估；首页执行/结果/推送建议筛选联动。
2. 定时评估默认开启、可关闭创建、切换后保存；立即执行继承开关且不改变周期。
3. 60条定时历史：50条首页、10条第二页；按异常筛选后显示30条，回到第1页，先过滤后分页。
4. 原始正文包含合法末尾标签，但页面正文隐藏精确标签；任务原始文本未改写，推送只显示建议。
5. 手动评估明确确认后只调用一次合成分类器，显示文本归类说明；result.json字节、任务完成状态和finished_at保持不变。
6. 页面切换不串结果；失败草稿手动评估不追加模型调用、不升级为已确认业务异常。
7. 普通任务主动开启后使用实际产品Factory/TaskService的原生交付逻辑，未构造额外Finalizer。
8. 390px宽度的新增定时开关与结果卡可操作且无页面横向溢出；不是整站移动端设计验收。
9. 上述场景没有JavaScript运行错误或非预期接口失败，筛选参数实际进入后端。此前undefined请求在固定ID后未再出现。

测试服务、临时任务目录和浏览器均已退出/清理；没有现场操作。初次浏览器地址受限与测试选择器调整不算产品通过记录，最终结果以修正后的完整场景执行为准。

## 产品边界保持

- 不新增业务模板、数值规则引擎或证据回灌审查。任务说明与有效用户指令仍提供异常判据，Skill提供业务语义。
- 自动判定使用同次原生答案的小标签；额外报告模型调用为0。标签错误进入需复核，不损坏原答案、不自动修复重试。
- 事后手动文本归类可能单独发起一次请求，需明确用户授权；有界输入/输出/通信超时，无工具、无图像、无Evidence、无自动重试。
- 失败/无数据与业务异常分开；推送建议不是已经发送，也不是独立可信度认证。
- 没有改Compose、Dockerfile、模型配置或业务算法，没有修改端侧服务。临时开发验证workflow和传输文件不留在最终功能树。
